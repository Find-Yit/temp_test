# 6 小时考核工作流模板（2026-09-14 模拟测试后整理，2026-09-15 正式考核使用）

## 分工
Fable（主会话）：读题、写计划、派任务、逐项独立验收、commit/push。
opus4.8 max：执行（环境、基线、改动实现、对照实验、评测脚本、一键脚本、README）。
opus4.6：LaTeX 报告写作（骨架/摘要/方法 → 基线结果 → 改动结果与分析）、给 GPT 的 md 说明。
opus5：调研（改进方向、先例核实、评测维度与指标）。

## 第 0 步（0–5 min）Fable
读题 PDF，探查机器（GPU/nvcc/python/网络），写 plans/总计划.txt。计划里一开始就写死：
- 所有产物中文命名；数值 json + txt 双份；考核提交/{网格,指标,可视化,日志,report.pdf}。
- 报告只五节（摘要/方法/数据集/结果/总结）；环境、代码差异、逐步命令只进 README；失败案例只写方法/超参层面；写作者不得加回用户删掉的内容。
- GitHub：.gitignore 排除 data/repo/venv/outputs/logs/cache/大点云；sugar_changes/ 放改动文件副本 + patch + 行号说明；scripts/一键复现/ 带 SMOKE 模式。
- 每阶段结束更新 checklist（防会话中断）。

## 第 1 波并行（0–40 min）
A 下载代码+数据（opus4.8）  B 装环境（opus4.8）  C 改进方向调研（opus5）
D 评测维度与指标调研（opus5）  E 报告 LaTeX 骨架 + 摘要占位（opus4.6，tectonic + Noto CJK）

## 第 2 波（40–70 min）
- C 完成后 → 派"先例核实"（opus5）：逐行核对源码/阈值/归属；Fable 据此定案并交用户审核。方案优先选"一次训练支撑多个消融"的改动（提取阶段或只需重跑短阶段）。
- B 通过后 → 派基线（opus4.8）：冒烟 → 正式（3DGS 7k → coarse 15k → 提取），任务里直接写明复制到 考核提交/。
- D 完成后 → 派评测脚本 M1–M6（opus4.8），任务里直接写明：合成数据自测 → 冒烟产物验证 → 等基线 mesh 出现自动跑基线评测。
- 方案定案后 → 同时派：改动实现（opus4.8，与基线训练并行，用冒烟产物验证开关）、方法节写作（opus4.6）、改动示意图说明 md（opus4.6，交 GPT 画图）、README（opus4.8，含环境/commit/diff）。

## 第 3 波（基线完成后）
- 验收基线（Fable 复算 V/F/连通分量/Chamfer）；基线结果写入报告（opus4.6）。
- 改动实现验收（复跑单测、git diff 审计）→ 派对照实验：先测超参曲线，再跑 3 个取值完整流程 + M2–M6 + 汇总对照表 + 复制到考核提交。

## 第 4 波（对照完成后，并行）
- Fable 复算改动 mesh 指标。
- 对比图 54 张 + 拼图说明 md（opus4.8，交 GPT 拼大图）。
- 改动结果/敏感性/失败案例/分析/总结/摘要回填（opus4.6），并把对比图组直接排进结果节（四列并排）。
- README 回填 + 代码改动位置.md + 一键脚本（SMOKE 真实跑通）（opus4.8）。

## 第 5 步 Fable 终验与交付
编译 PDF → 渲染缩略图目视检查 → 复制到 考核提交/ → 去掉报告中的工程细节 → git init/.gitignore/commit → 用户确认署名与推送 → push。
用户人工节点：审核方案；GPT 画示意图与大对比图；报告终稿修改。

## 今天的教训
- 调研文档的"借鉴 X"必须核源码，否则会被考官问住。
- 评测口径（bbox 裁剪、顶点计数、采样数、seed）全程统一，基线与改动用同一脚本同一参数。
- 会话可能中断：子代理任务要让其在 RUNLOG 逐步落盘，便于续跑。

# 先例核实：Poisson 前的多视角深度一致性剔点（2026-09-14）

## TL;DR
1. **Gaussian Surfels 的 volumetric cutting 不是多视角深度投票**，是"从高斯建 512³ 占据栅格 → 剔除落在空体素的深度图点"。照搬"移植 Gaussian Surfels 的 volumetric cutting"这句话会被问住。
2. 我们方案真正的祖宗是 **COLMAP StereoFusion / ACMM 的几何一致性融合**（相对深度差 + 投票计数），以及 **GaussianPro** 把它搬进 3DGS 的实现。阈值全部可引用。
3. **没有人把它用在 SuGaR 的 Poisson 之前**；但同作者的 **Frosting 在同一套提取代码里加了"多视角可见性 + 连通分量"清理**，是最近的直接先例（位置在 Poisson 之后）。
4. 候选 B 的可抄先例是 **GaussianPro 的 `flatten_loss`（λ=100）**；Gaussian Surfels 是硬压扁不是正则；**GaussianShader 没有 flatten loss，不要引用**。

## 一、先例核实（Q1）

### A. Gaussian Surfels 的 volumetric cutting（核实结果与预期不符）
论文 SIGGRAPH 2024，<https://arxiv.org/abs/2404.17774>；代码 <https://github.com/turandai/gaussian_surfels>

| 项 | 位置 | 默认值 |
|---|---|---|
| 建占据栅格 | `scene/gaussian_model.py:555 to_occ_grid()`（CUDA `gaussian2occgrid`，累加加权不透明度） | `cutoff=0.0, grid_dim_max=512` |
| 剔点 | `utils/image_utils.py:409 grid_prune()`，调用于 `render.py:58` | `thrsh=1`（体素累计值 > 1 才保留） |
| 可见性 / 深度裁剪 | `render.py:49-51` | `opac > 1e-5`；`depth_range=[0, 20]` |
| Poisson + 剪枝 | `utils/general_utils.py:212 poisson_mesh()`，调用于 `render.py:89` | `poisson_depth=10, samplespernode=1.5`；`prune_thrsh=3e-5`（顶点到采样点 knn 距离 `q>3e-5` 则删）；`meshing_close_holes(maxholesize=300)`；拉普拉斯平滑 3 次 |

**关键**：判据是"点是否落在高斯自己撑起的占据体素里"，**没有跨视角深度比较**。仓库里确实有多视角投票函数 `mask_prune(pts, cams, pad=4)`（`utils/image_utils.py:396`，用 object mask 而非深度），但在 `render.py:59` 被注释掉：`clean_mask = grid_mask #* mask_mask`。

### B. MVS 经典几何一致性（我们方案的真正出处）
- **COLMAP** <https://github.com/colmap/colmap>：`src/colmap/mvs/fusion.h` `StereoFusionOptions` = `max_reproj_error=2.0`（像素）、`max_depth_error=0.01`、`max_normal_error=10.0`（度）、`min_num_pixels=5`、`max_num_pixels=10000`、`check_num_images=50`、`max_traversal_depth=100`。判据实现在 `src/colmap/mvs/fusion.cc:395`：
  `depth_error = |(proj.z − depth)/depth|` → 正是**相对深度差**，默认 τ = 0.01。
- **ACMM** <https://github.com/GhiXu/ACMM>：`main.cpp:257,273`
  `if (reproj_error < 2.0f && relative_depth_diff < 0.01f && angle < 0.174533f) num_consistent++;` … `if (num_consistent >= 2) {保留}`（0.174533 rad = 10°）。
- **GaussianPro**（ICML 2024）<https://github.com/kcheng1021/GaussianPro>：`utils/graphics_utils.py:338`
  `check_geometric_consistency(..., thre1=1, thre2=0.01)`，源码注释即 `# check |p_reproj-p_1| < 1` / `# check |d_reproj-d_1| / d_1 < 0.01`；`train.py:172` 实际以 `thre1=2, thre2=0.01` 调用，`train.py:179` `cost_mask = cost >= 2`（至少 2 个源视角一致）。另有退火阈值 `depth_error_min/max_threshold=1.0`（`arguments/__init__.py:108-109`）。

### C. 2DGS / PGSR / GOF / RaDe-GS 的提取阶段（都**不是**显式多视角投票）
- **2DGS** <https://github.com/hbb1/2d-gaussian-splatting>：Open3D TSDF（隐式多视角平均）+ `utils/mesh_utils.py:21 post_process_mesh(mesh, cluster_to_keep=1000, min_cluster_size=50)`；`render.py` 默认 `--num_cluster 50`、`depth_trunc=2·radius`、`voxel_size=depth_trunc/1024`、`sdf_trunc=5·voxel_size`。训练正则 `lambda_normal=0.05, lambda_dist=0.0`（`arguments/__init__.py:86-87`）。
- **PGSR** <https://github.com/zju3dv/PGSR>：`render.py:105-112` 提取期只有**掠射角过滤**（深度法向与视线夹角 > 80° 置 0）；TSDF `voxel_size=0.002, sdf_trunc=4·voxel_size, max_depth=5.0, num_cluster=1`。真正的多视角一致性在**训练**：`arguments/__init__.py` `multi_view_num=8, max_angle=30, min_dis=0.01, max_dis=1.5, geo_weight=0.03, ncc_weight=0.15, patch_size=3, pixel_noise_th=1.0, from_iter=7000, use_multi_view_trim=True`。
- **RaDe-GS** <https://github.com/BaowenZ/RaDe-GS>：`mesh_extract_tnt.py` 与 PGSR 同款（80° 过滤 + TSDF `sdf_trunc=4·voxel_size`、`voxel_size=max_dis/2048` + `post_process_mesh`）。
- **GOF** <https://github.com/autonomousvision/gaussian-opacity-fields>：`extract_mesh_tsdf.py` `voxel_size=0.002`；主线是 Marching Tetrahedra，无投票。
- **gaustudio**（最接近"投票"的开源实现）<https://github.com/GAP-LAB-CUHK-SZ/gaustudio>：`gaustudio/scripts/extract_mesh.py:145` VDB TSDF `extract_triangle_mesh(min_weight=5)` —— 体素至少被 5 个视角写入才保留，是体素版的多视角投票；`--clean` 走连通分量、`ratio_threshold=0.5`。

## 二、有人在 SuGaR 上做过吗（Q2）

**没有**在 SuGaR 的 Poisson 之前对表面采样点做多视角深度一致性投票的公开实现：`Anttwo/SuGaR` 无相关 issue/PR，未检索到这样的 fork；本地 `sugar_extractors/coarse_mesh.py` 只有 `remove_statistical_outlier(nb_neighbors=20, std_ratio=20.)` 与 `vertices_density_quantile=0.1`。

**但同作者的 Frosting 在同一套提取代码里加了清理步骤**（ECCV 2024 Oral，<https://github.com/Anttwo/Frosting>）：
`frosting_extractors/coarse_shell.py:566-617` `remove_nonvisible_connected_components`（`:84` 硬编码为 True）——用 PyTorch3D `MeshRasterizer` 遍历**全部训练相机**统计每个三角面被看到的次数，再按 `cluster_connected_triangles()` 求 `cluster_visibility_ratio = 可见面数 / 该分量面数`，比值 `< cluster_visibility_threshold` 的分量整块删除。默认值 `--connected_components_vis_th 0.001`、`--cleaning_quantile 0.1`（`train_full_pipeline.py:33,36`）。
→ 与我们的差别：在 **Poisson + decimate 之后**，粒度是**连通分量**，判据是"**是否被看到**"而非"深度是否一致"。

其余同作者工作不是这件事：MILo `milo/functional/mesh.py:11 frustum_cull_mesh`（视锥裁剪）；MAtCha `2d-gaussian-splatting/extract_mesh.py:331 filter_mesh`（`distance <= scale`，按高斯尺度剔四面体顶点）。相关但设定不同：FreeSplat++ 的 Weighted Floater Removal（前馈式 3DGS，按多视角深度一致性**降不透明度**而非剔点，无代码）<https://wangys16.github.io/FreeSplatPP-Page>。

## 三、归属表述（Q3）

**"借鉴 Gaussian Surfels 的 volumetric cutting 移植到 SuGaR" 不成立**（判据完全不同，见 §一.A）。

**最准确的一句话**：
> 把 MVS 标准的多视角几何一致性融合判据（COLMAP `StereoFusion` 的相对深度差 `max_depth_error=0.01` + ACMM 的 `num_consistent≥2` 投票；GaussianPro `check_geometric_consistency` 是其 3DGS 版本）移植到 SuGaR 的 Poisson 前表面点云上；动机与 Gaussian Surfels 的 volumetric cutting、Frosting 的 non-visible connected component removal 一致——都是在表面重建前剔除只在单一视角自洽的点。

**与先例的两处具体差异**（写进报告）：
1. **判据形式**：COLMAP/ACMM/GaussianPro 是"深度图 → 源视角 → 回投参考视角"的**前向-后向重投影**，同时卡像素重投影误差（1–2 px）与相对深度差（0.01）；我们是"3D 表面点 → 其它相机渲染深度图"的**单向投影**，只有相对深度差、**没有重投影误差项、不做回投**（因为点本身就是 3D 的，无需回投取点）。
2. **过滤对象与插入位置**：Gaussian Surfels 过滤深度图像素点（占据栅格判据）、Frosting 过滤 Poisson 之后的 mesh 连通分量（可见性比例判据）；我们过滤的是 SuGaR 沿射线取密度等值面得到的**表面采样点**，位置在 **fg/bg 分离与 Poisson 之前**——这个插入点目前无先例代码。
3.（可选，作为"我们的小创新"）我们额外区分**空域冲突票**（`z_p < z_map − τ·z_map`，点浮在已知表面之前）与普通不一致，COLMAP/ACMM 只有一致/不一致二元。

## 四、候选 B（扁平化正则）的先例（Q4）

| 先例 | 位置 | 形式与默认值 |
|---|---|---|
| **GaussianPro**（可直接抄） | `train.py:216-222`；开关 `arguments/__init__.py:88,93` | `min_scale=min(get_scaling,dim=1).clamp(0,30)`；`loss += lambda_flatten * abs(min_scale).mean()`；**`lambda_flatten=100.0`** |
| **Gaussian Surfels**（硬压扁，非正则） | `scene/gaussian_model.py:182` 与 `:455` | `scales[...,-1] -= 1e10` / `new_scaling[:,-1] = -1e10` → z 尺度 = 0 |
| **2DGS**（表示层面，非正则） | `arguments/__init__.py:86-87` | 基元本身是 2D 圆盘；代码默认 `lambda_normal=0.05, lambda_dist=0.0`；论文实现细节为 α(distortion)=1000（bounded/DTU）、100（unbounded），β(normal)=0.05 |
| **GaussianShader** | `arguments/__init__.py:111-113` | **无 flatten loss**（只有 `lambda_predicted_normal=0.2, lambda_zero_one=1e-3, lambda_delta_reg=1e-3`）——**不要引用它** |

**归属表述**：
> 移植 GaussianPro 的 `flatten_loss`（`torch.abs(min_scale).mean()`，λ=100）到 SuGaR 的 coarse `dn_consistency` 训练，并把**绝对 s_min 改为尺度无关的比值 s_min/s_mid**，避免与 SuGaR 的 density 正则争夺全局尺度。差异即 abs → ratio，以及生效步数（第 7000 步起，对齐 PGSR/GaussianPro 的 `from_iter=7000`）。

## 五、一个"先例更强、移植更省事"的替代方案（Q5，≤200 字）

**直接移植 Frosting 的 `remove_nonvisible_connected_components`**（`coarse_shell.py:566-617`，约 50 行）。它与 SuGaR `coarse_mesh.py` 出自同一作者、同一份代码骨架，变量名几乎一致，复制即可跑；先例强度最高（ECCV'24 Oral 官方实现），超参 `connected_components_vis_th` 天然可扫 {0.001, 0.1, 0.5}，且直接产出假设 H1 的"连通分量数"指标。**风险**：它位于 Poisson + decimate 之后，可能被判为"最后一层后处理"（题目排除项）。建议把它作为候选 A 的**对照/组合项**，或把可见性统计从"光栅化 mesh"前移为"投影表面点"，使其落在 Poisson 之前。
